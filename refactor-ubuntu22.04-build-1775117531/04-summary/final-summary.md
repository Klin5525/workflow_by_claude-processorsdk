## 项目背景

### 原始需求

重构 ubuntu22.04 编译脚本，解决以下四个问题：

1. **清理内核 defconfig 中无用驱动**：内核安装时找不到驱动的报错
2. **去除软件源更新操作**：`apt-get update` 非常占用时间
3. **删除非 src-lite 版型**：减少维护复杂度
4. **更新文档**：记录优化内容和效果

### 技术背景

- **目标平台**：Rockchip RK3562 + Ubuntu 22.04
- **设备场景**：src-lite 智能网关（无头设计，无 GPU/显示/音频）
- **WiFi 模块**：移远 FC06E（仅 WiFi，无蓝牙）
- **构建系统**：Rockchip Linux SDK + 自定义构建脚本

## 经验教训

### 成功经验

1. **第一性原理思考**：
   - 从网关的实际需求出发（无 GPU/显示/音频/蓝牙）
   - 质疑所有"默认保留"的配置
   - 验证 FC06E 驱动包的真实功能（发现无蓝牙）

2. **分层验证策略**：
   - 快速验证（语法检查）→ 发现明显错误
   - 完整验证（构建测试）→ 发现依赖问题
   - 回归验证（功能测试）→ 确保功能完整

3. **详细文档记录**：
   - 每个 agent 记录操作日志
   - 生成专项报告（架构/实现/测试）
   - 更新用户文档（.claude/ubuntu22.04.md）

### 失误教训

1. **配置依赖检查不足**（Bug #001）：
   - **问题**：删除 CONFIG_I2C=y，但保留了依赖 I2C 的驱动
   - **原因**：工程师仅执行语法检查，未完整构建
   - **改进**：删除配置前使用 `make menuconfig` 检查依赖关系

2. **设计文档与实现不一致**：
   - **问题**：文档声明保留 CONFIG_I2C，实际误删
   - **原因**：工程师未严格遵循架构文档
   - **改进**：实现时逐项对照设计文档，使用 checklist

3. **测试验证不完整**：
   - **问题**：工程师仅语法检查，未完整构建
   - **原因**：追求速度，跳过耗时的构建测试
   - **改进**：至少执行一次完整构建，确保可编译

### 流程改进建议

   - ✅ 使用用户决策工具（AskUserQuestion）确认关键决策

   - **验证方式**：回归测试验证保留驱动存在
